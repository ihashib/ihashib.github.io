Java basics2 topics

Java basics

Compile and run from the terminal

javac Hello.java      # compile: makes Hello.class (bytecode)
java Hello            # run it on the JVM

# a project with packages: compile into target/
javac -d target -sourcepath src src/service/CarService.java src/model/*.java

The five phases of a Java program

  1. Edit: write the source code (.java).
  2. Compile: javac turns it into bytecode (.class), which the JVM understands.
  3. Load: the JVM's class loader reads the bytecode.
  4. Verify: the JVM checks the bytecode is safe to run.
  5. Execute: the JVM runs it, compiling hot parts to machine code as it goes (JIT).

Because every platform has a JVM, the same .class file runs anywhere: "write once, run anywhere".

Operators and formatting

Kind Operators
Arithmetic + - * / %
Unary +x (same value), -x (sign flipped), ++x / x++, --x / x--
Relational > < >= <= == !=
Logical && || !
Ternary cond ? a : b: a if cond is true, else b

-x flips the sign: if x = -10, then -x is 10. +x leaves it alone.

System.out.printf("price = %.2f%n", 3.14159);   // price = 3.14
String label = age >= 18 ? "adult" : "child";

Escape sequences: \n new line, \t tab, \" quote, \\ backslash.

Wrapper classes, autoboxing and unboxing

Each primitive has an object version (int → Integer, double → Double, char → Character...). Collections can only hold objects, so Java converts automatically:

int x = 5;
Integer boxed = x;        // autoboxing: int → Integer
int y = boxed;            // unboxing: Integer → int

Unboxing a null Integer throws a NullPointerException.

Memory and garbage collection

Stack Heap
Holds Method calls, local variables, references Objects and arrays
Lifetime Until the method returns Until nothing refers to it
Speed Very fast (LIFO) Slower; managed by the GC
Shared? One per thread Shared by all threads

Garbage collection

Java frees memory for you. When no reference points to an object any more, the garbage collector reclaims it.

The heap is split by age, because most objects die young:

  • Young generation: new objects. Cleaned often and quickly.
  • Old generation: objects that survived several cleanups. Cleaned less often.

You can suggest a collection with System.gc(), but the JVM decides when it really happens.

Java OOP14 topics

Object-oriented programming

OOP organises a program around objects: bundles of data (fields) and behaviour (methods) that model real things, like a Car with a speed and an accelerate() method.

Class

A class is a blueprint: it says which fields and methods its objects will have.

class Car {
    String model;
    int speed;
    void accelerate() { speed += 10; }
}

Object

An object is one instance built from a class, with its own values.

Car a = new Car();   // one car
Car b = new Car();   // another, independent car
a.accelerate();      // only a speeds up

The four pillars of OOP

Pillar Idea in one line
Encapsulation Keep data private; expose only what's needed
Inheritance Build a class on top of another and reuse its code
Polymorphism One call, different behaviour depending on the object
Abstraction Show what something does, hide how

Inheritance

A subclass gets the fields and methods of its superclass, and can add or change them. It's an "is a" relationship: a car is a vehicle.

class Vehicle {
    protected int gear;
    protected int speed;

    Vehicle(int gear, int speed) { this.gear = gear; this.speed = speed; }

    void shiftGear(int gear) { this.gear = gear; }
}

class Car extends Vehicle {
    private final int carType;

    Car(int carType, int gear, int speed) {
        super(gear, speed);        // the parent's constructor runs first
        this.carType = carType;
    }
}
  • private members aren't visible to subclasses; use protected for what children need.
  • Types: single (B extends A), multilevel (C extends B extends A), hierarchical (B and C both extend A).
  • Multiple inheritance of classes (C extends A and B) isn't allowed, because of the diamond problem. A class can implement many interfaces.

Polymorphism

"Many forms": the same method call does different things.

Compile-time (static) Runtime (dynamic)
How Overloading: same name, different parameters Overriding: a subclass replaces a parent method
Decided By the compiler, from the argument types By the JVM, from the real object 
class Animal { void speak() { System.out.println("..."); } }
class Dog extends Animal { @Override void speak() { System.out.println("Woof"); } }

Animal a = new Dog();   // upcasting: a parent reference to a child object
a.speak();              // "Woof": the object's real class decides

Overriding rules: same name and parameters, a compatible return type, not less visible. final, static and private methods can't be overridden, and neither can constructors. Fields are never polymorphic, only methods.

Abstraction

Hide the details and show only what something does. Two tools:

Abstract class Interface
Keyword abstract class, extends interface, implements
Methods Abstract and concrete Abstract, plus default and static methods (Java 8+)
Fields Any Only public static final constants
Constructor Yes (runs when a child is created) No
A class can have One parent Many interfaces
Use for Shared code in a family of classes A capability ("can be printed", "can be compared") 
abstract class Bike {
    abstract void run();                        // children must write this
    void honk() { System.out.println("Beep"); } // shared code
}
class Honda extends Bike {
    @Override void run() { System.out.println("Running safely"); }
}

interface Printable { void print(); }
class Report implements Printable {
    public void print() { System.out.println("Report"); }
}

An abstract class can't be instantiated (new Bike() fails), but its constructor still runs when you create a Honda.

Encapsulation

Keep fields private and give controlled access through methods. The class can then check values and change its insides without breaking anyone.

public class Account {
    private double balance;

    public double getBalance() { return balance; }

    public void deposit(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("Amount must be positive");
        balance += amount;
    }
}

Benefits: data hiding, safer changes, reuse.

A package groups related classes and interfaces (java.util, com.example.shop.model).

Coupling

Coupling is how much one class depends on the details of another.

  • Tight coupling: a class knows and uses another's internals. Change one and the other breaks.
  • Loose coupling: classes talk through small, stable interfaces. Aim for this.

Private fields, interfaces and dependency injection all loosen coupling.

Cohesion

Cohesion is how closely the parts of a class (or package) belong together.

  • High cohesion: everything serves one clear purpose, like java.io, which is all about input and output. Aim for this.
  • Low cohesion: unrelated things lumped together, like a "utilities" grab bag.

Good design: high cohesion, loose coupling.

Association

Association is any relationship between objects: a teacher teaches students.

  • It can be one-way (an order knows its customer) or two-way (each knows the other).
  • Multiplicity: one-to-one, one-to-many, many-to-one, many-to-many.

Aggregation and composition

Two special kinds of association, both "has a":

Aggregation Composition
Ownership Weak: the part can live alone Strong: the part belongs to the whole
If the whole goes The parts survive The parts go too
Example A department has students A house has rooms 
class Department {                       // aggregation: students come from outside
    private final List<Student> students;
    Department(List<Student> students) { this.students = students; }
}

class House {                            // composition: the house makes its own rooms
    private final List<Room> rooms = List.of(new Room("Kitchen"), new Room("Bedroom"));
}

Constructors

A constructor sets up a new object. It runs when you write new.

  • It has the same name as the class and no return type.
  • It can't be abstract, static, final or synchronized.
  • You can overload constructors (several with different parameters).
Kind Notes
Default Added by Java only if you write no constructor at all
No-args One you write that takes no parameters
Parameterised Takes values for the fields 
class Point {
    int x, y;
    Point() { this(0, 0); }                         // no-args: calls the other one
    Point(int x, int y) { this.x = x; this.y = y; } // parameterised
}

static

static means "belongs to the class, not to any one object".

Static variables

One copy shared by all objects.

class Counter {
    static int total;   // shared
    int mine;           // one per object
}

Counter.total = 5;
Counter c = new Counter();
c.mine = 6;
c.total = 7;                      // the same shared variable (better written Counter.total)
System.out.println(Counter.total);   // 7

Static methods

Called on the class, with no object needed. That's why main is static.

  • They can't use instance fields or methods directly.
  • They can't use this or super.
class MathUtil {
    static int square(int n) { return n * n; }
}
MathUtil.square(4);   // 16

Static blocks

Run once, when the class is first loaded (before main), to set up static variables.

class Config {
    static final Map<String, String> DEFAULTS = new HashMap<>();
    static {
        DEFAULTS.put("lang", "en");
    }
}

Kinds of variables

Kind Declared Lives Default value?
Local Inside a method Until the method returns No: must be set before use
Instance In the class, outside methods As long as the object Yes (0, false, null)
Static In the class, with static As long as the program Yes

When a local variable has the same name as a field, the local one wins. Use this.name to reach the field.

Pass by value

Java is always pass-by-value. The question is what the value is:

  • Primitives: the value itself is copied. Changing it inside the method doesn't affect the caller.
  • Objects: the reference is copied. Both copies point to the same object, so changes to the object's fields are visible to the caller, but reassigning the parameter isn't.
class Box { int a; }

static void change(Box b) {
    b.a = 4;           // changes the shared object: the caller sees 4
    b = new Box();     // points the local copy elsewhere: the caller doesn't see this
    b.a = 99;
}

Box t = new Box();
change(t);
System.out.println(t.a);   // 4

super, final and this

super

Refers to the parent class.

class Child extends Parent {
    Child(int x) {
        super(x);              // the parent's constructor: must be the first line
    }
    @Override void foo() {
        super.foo();           // run the parent's version too
        System.out.println("child foo");
    }
    int parentNum() { return super.num; }   // a parent field hidden by a child field
}

this

Refers to the current object: this.name = name;. this(...) calls another constructor of the same class.

final

"Can't be changed":

On Means
A variable Assigned once, never again
A blank final field (final int a;) Must be set in every constructor
A static final field A constant; set where declared or in a static block
A method Subclasses can't override it (they still inherit it)
A class Can't be extended (like String)

final on an object reference stops reassigning the variable, not changing the object: a final List can still have items added.

Annotations: @Nullable

Annotations are labels on code that tools, the compiler or frameworks can read (@Override, @Deprecated, @FunctionalInterface...).

@Nullable marks something that may be null:

public @Nullable User findByEmail(String email) { ... }   // may return null

void greet(@Nullable String name) {
    System.out.println("Hi " + (name != null ? name : "there"));
}

Use it on parameters, return values and fields. IDEs and tools like SpotBugs or NullAway then warn you where a null isn't handled, catching NullPointerExceptions before they happen. Its opposite is @NonNull.

For return values, Optional<User> is often clearer than a nullable return.

Async and lambdas3 topics

Async Java: CompletableFuture

A CompletableFuture is a value that will be ready later. Work runs in the background (on a thread pool), so the calling thread isn't blocked, and you can chain and combine steps.

When to use it

  • I/O-bound work: network calls, database queries, files.
  • Several independent tasks that can run at the same time.
  • Background jobs and timeouts.

If the work is quick and done step by step, plain synchronous code is simpler.

Create

CompletableFuture<String> ready = CompletableFuture.completedFuture("Hello");   // already done

CompletableFuture<String> f = CompletableFuture.supplyAsync(() -> fetchUser()); // returns a value
CompletableFuture<Void>   g = CompletableFuture.runAsync(() -> sendEmail());    // returns nothing

String user = f.join();                          // wait for the result
String u2 = f.get(2, TimeUnit.SECONDS);          // wait at most 2 s, else TimeoutException

Chain

CompletableFuture<Integer> length = f.thenApply(String::length);          // plain function
CompletableFuture<Order>   order  = f.thenCompose(u -> fetchOrderAsync(u)); // function that returns a future
f.thenAccept(System.out::println);                                         // use the result, return nothing

thenApply vs thenCompose is like map vs flatMap: use thenCompose when your function itself returns a CompletableFuture.

Combine

CompletableFuture<String>  name = CompletableFuture.supplyAsync(() -> "Rafi");
CompletableFuture<Integer> age  = CompletableFuture.supplyAsync(() -> 20);

CompletableFuture<String> both = name.thenCombine(age, (n, a) -> n + " is " + a);   // two futures
CompletableFuture<Void>   all  = CompletableFuture.allOf(f1, f2, f3);    // wait for every one
CompletableFuture<Object> any  = CompletableFuture.anyOf(f1, f2, f3);    // the first to finish

Handle errors

f.exceptionally(ex -> "fallback");                              // only on failure
f.handle((result, ex) -> ex == null ? result : "fallback");     // always: result or error

Functional interfaces

A functional interface has exactly one abstract method. That's what lets you pass behaviour around as a value, using a lambda or a method reference.

The four you'll use most (java.util.function):

Interface Takes Returns Use it to Example
Function<T, R> T R Transform user -> user.getEmail()
Predicate<T> T boolean Test or filter user -> user.isActive()
Consumer<T> T nothing Do something with it msg -> System.out.println(msg)
Supplier<T> nothing T Create on demand () -> Math.random() 
Function<User, String> email = User::getEmail;
Predicate<User> active = u -> u.getStatus() == Status.ACTIVE;
Consumer<String> printer = System.out::println;
Supplier<List<String>> newList = ArrayList::new;

users.stream().filter(active).map(email).forEach(printer);

Others: BiFunction<T, U, R> (two inputs), UnaryOperator<T> (T → T), Runnable (nothing → nothing). Mark your own with @FunctionalInterface.

Lambdas and method references

A lambda is a short anonymous function: (parameters) -> body.

Runnable hello = () -> System.out.println("Hello");
Comparator<String> byLength = (a, b) -> a.length() - b.length();
Function<Integer, Integer> square = x -> x * x;
BinaryOperator<Integer> add = (a, b) -> {
    int sum = a + b;      // a block body needs braces and return
    return sum;
};
  • One parameter needs no brackets: x -> x * x.
  • Types are usually inferred; write them only if it helps: (String s) -> s.length().
  • A lambda can use local variables from outside only if they're effectively final (never reassigned).

Method references

A shorter lambda when it just calls one method:

Kind Method reference Same as
Static method Integer::parseInt s -> Integer.parseInt(s)
Method of a given object System.out::println x -> System.out.println(x)
Method of the argument String::toUpperCase s -> s.toUpperCase()
Constructor ArrayList::new () -> new ArrayList<>() 
List<String> names = List.of("rafi", "nila", "tamim");
names.stream().map(String::toUpperCase).sorted().forEach(System.out::println);
Threading7 topics

Process

A process is a running program, with its own memory. Processes don't share memory with each other. A process contains one or more threads.

Thread

A thread is one path of execution inside a process. Threads of the same process share its memory (the heap), which makes them light, but means they must be careful with shared data.

Multitasking

Multitasking is a computer running several jobs (processes) at the same time, or switching between them so fast it looks that way.

Multithreading

Multithreading is one program running several threads at once: for example a UI thread staying responsive while a worker thread downloads a file.

The main thread

When you start a Java program, the JVM creates the main thread, which runs main(). When main returns and no other (non-daemon) threads are running, the program ends.

Threads sharing memory

  • Each thread has its own stack: if two threads run the same method, each gets its own copy of the local variables.
  • All threads see the same heap: two threads can read and change the same object or static field at the same time.
  • That's where bugs come from: race conditions, where the result depends on timing. Protect shared data with synchronized, locks or thread-safe classes (AtomicInteger, ConcurrentHashMap).

Creating and controlling threads

1. Implement Runnable (preferred)

class Task implements Runnable {
    @Override
    public void run() {
        System.out.println("Running on thread " + Thread.currentThread().getId());
    }
}

Thread t1 = new Thread(new Task());
Thread t2 = new Thread(() -> System.out.println("A lambda works too"));
t1.start();
t2.start();

2. Extend Thread

class Worker extends Thread {
    @Override
    public void run() {
        try {
            Thread.sleep(100);           // pause 100 ms
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        System.out.println("Done " + getId());
    }
}
new Worker().start();

Prefer Runnable: your class stays free to extend something else, and the task is separate from the thread that runs it.

Call start(), not run(). run() just runs the code on the current thread; start() creates a new one.

join(): wait for a thread to finish

start() returns at once, so the next line may run before the thread is done. join() waits.

t1.start();
t2.start();
t1.join();      // throws InterruptedException
t2.join();
System.out.println(count);   // safe: both threads have finished

synchronized: one thread at a time

When threads change the same data, updates can be lost (count++ is really read, add, write). synchronized lets only one thread in at a time.

private static int count = 0;

public static synchronized void increase() {
    count++;
}

Simpler for counters: AtomicInteger count = new AtomicInteger(); count.incrementAndGet();

In real apps, use an ExecutorService (a thread pool) instead of creating threads by hand: Executors.newFixedThreadPool(4).submit(task).

Big O and complexity

Big O describes how the time (or memory) an algorithm needs grows as the input grows, ignoring constants.

Notation Describes
O (Big O) An upper bound: usually quoted for the worst case
Ω (Big Omega) A lower bound: often the best case
Θ (Big Theta) A tight bound: both at once
Complexity Name Typical example
O(1) Constant Array access by index, HashMap get
O(log n) Logarithmic Binary search
O(n) Linear One loop over the input
O(n log n) Linearithmic Merge sort, heap sort
O(n²) Quadratic Two nested loops, bubble sort
O(n³) Cubic Three nested loops
O(2ⁿ) Exponential Naive recursive Fibonacci, all subsets
O(n!) Factorial All orderings (permutations)

Where log n comes from

log₂ 8 = 3 because 2³ = 8. If each step halves the input, n reaches 1 after log₂ n steps:

while (n > 1) {
    n = n / 2;       // 8 → 4 → 2 → 1: three steps for n = 8
}

Run that halving loop inside a loop of n steps and you get O(n log n).

Working out the complexity

  1. Split the code into parts and find each part's cost.
  2. Parts one after another add; nested parts multiply.
  3. Keep only the biggest term and drop constants: O(2n² + 3n + 5) → O(n²).

Space complexity counts extra memory the same way: a few variables are O(1); a new array of size n is O(n).

Arrays and strings

Operation Array ArrayList String
Read by index O(1) O(1) O(1) (charAt)
Search O(n) O(n) O(n) (indexOf)
Add at the end fixed size O(1) on average new string: O(n)
Insert or delete in the middle O(n) O(n) new string: O(n)
  • Arrays have a fixed size; ArrayList grows by copying into a bigger array.
  • String is immutable: every change makes a new string. Build strings in a loop with StringBuilder, otherwise the loop becomes O(n²).
StringBuilder sb = new StringBuilder();
for (String w : words) sb.append(w).append(' ');
String sentence = sb.toString();
  • Two pointers (one from each end) and the sliding window are the classic array and string techniques.

Hash tables

A hash function turns a key of any size into a fixed-size number: a fingerprint of the key. A hash table uses it to choose an array slot:

int index = Math.abs(key.hashCode()) % table.length;

So finding, adding and removing are O(1) on average.

Example: with 10 slots and hash(x) = x % 10, the keys 11, 12 and 13 go to slots 1, 2 and 3. Key 21 also goes to slot 1: a collision.

Handling collisions by chaining: each slot holds a linked list of key–value pairs. To find a key, go to its slot and walk the list. With a good hash function the lists stay short.

My implementation

In Java, use HashMap. Objects used as keys must override both equals() and hashCode(), consistently.

DSA: collections6 topics

The Collections Framework

The Collections Framework (java.util, since Java 1.2) is Java's set of ready-made data structures.

Queue

A queue is first in, first out (FIFO), like a line at a shop.

Method Does If empty
offer(e) / add(e) Add at the back
poll() Remove and return the front returns null
remove() Remove and return the front throws
peek() Look at the front, don't remove returns null
size(), isEmpty(), contains(e), clear() The usual 
Queue<String> q = new LinkedList<>();    // or new ArrayDeque<>()
q.offer("a");
q.offer("b");
q.poll();                                // "a"

for (String s : q) System.out.print(s + " ");   // iterate

Priority queue

A PriorityQueue always hands out the highest-priority element first, not the oldest. It's built on a heap, so adding and removing are O(log n) and peeking is O(1).

PriorityQueue<Integer> min = new PriorityQueue<>();                            // smallest first (default)
PriorityQueue<Integer> max = new PriorityQueue<>(Collections.reverseOrder());  // largest first

min.addAll(List.of(3, 5, 6, 1));
min.poll();   // 1
max.addAll(List.of(3, 5, 6, 1));
max.poll();   // 6

Ordering your own objects

  • Comparable: the class knows how to compare itself ("I know my order"). Implement compareTo.
  • Comparator: an outside judge, passed in. Build one with Comparator.comparing(...), chain with thenComparing(...).
PriorityQueue<Task> tasks = new PriorityQueue<>(
        Comparator.comparingInt(Task::priority).thenComparing(Task::name));

The compare contract: a negative result puts a first, positive puts b first, zero means equal.

Top-k trick: to keep the k largest items, use a min-heap of size k and drop the smallest whenever it grows past k. For the k smallest, use a max-heap.

ArrayDeque

ArrayDeque is a double-ended queue ("deck"): add and remove at both ends in O(1). It's the best choice for both a queue and a stack in Java.

Front Back
addFirst(e) / offerFirst(e) addLast(e) / offerLast(e)
removeFirst() / pollFirst() removeLast() / pollLast()
getFirst() / peekFirst() getLast() / peekLast() 
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1);
stack.push(2);
stack.pop();      // 2: last in, first out

Deque<Integer> queue = new ArrayDeque<>();
queue.offer(1);
queue.offer(2);
queue.poll();     // 1: first in, first out

poll/peek return null when empty; remove/get throw an exception.

List

A List is an ordered collection that allows duplicates, accessed by index.

Common methods

Method Does
add(e) / add(i, e) Append / insert at index i
get(i) / set(i, e) Read / replace at index i
remove(i) / remove(obj) Remove by index / the first equal object
indexOf(e) The first index of e, or −1
contains(e), size(), isEmpty(), clear() The usual
toArray() Copy into an array

Which list?

Class Built on Fast at Slow at Thread-safe
ArrayList A growing array Reading by index O(1) Inserting in the middle O(n) No
LinkedList A doubly linked list Adding or removing at the ends O(1) Reading by index O(n) No
Vector A growing array Like ArrayList Every call is synchronized Yes (legacy)
Stack Vector push, pop Yes (legacy)
  • ArrayList grows by 50% when full; Vector doubles.
  • Default choice: ArrayList. For a stack or queue, use ArrayDeque instead of Stack or LinkedList.

Stack (last in, first out)

Stack<Integer> s = new Stack<>();
s.push(1);
s.push(2);
s.peek();     // 2, still there
s.pop();      // 2, removed (EmptyStackException if empty)
s.search(1);  // 1: its position from the top, or -1
s.empty();    // false

Map

A Map stores key → value pairs. Keys are unique: putting an existing key replaces its value. Map is not a Collection.

Class Order Notes
HashMap None The default. O(1) on average. One null key allowed.
LinkedHashMap Insertion order Also handy for LRU caches
TreeMap Sorted by key O(log n). firstKey(), floorKey(), ranges
Hashtable None Legacy and synchronized; use ConcurrentHashMap instead 
Map<Character, Integer> counts = new HashMap<>();   // keys and values must be objects (Character, Integer)
for (char c : "banana".toCharArray()) {
    counts.merge(c, 1, Integer::sum);               // add 1, starting at 1
}
// {a=3, b=1, n=2}

counts.get('a');                  // 3
counts.getOrDefault('z', 0);      // 0
counts.containsKey('b');          // true
counts.remove('b');
for (Map.Entry<Character, Integer> e : counts.entrySet()) {
    System.out.println(e.getKey() + " → " + e.getValue());
}

Also: put, containsValue, keySet(), values(), size(), isEmpty(), clear(), equals().

Set

A Set holds unique elements: adding a duplicate does nothing (add returns false).

Class Order Speed
HashSet None O(1) on average
LinkedHashSet Insertion order O(1) on average
TreeSet Sorted O(log n); first(), ceiling(), ranges
EnumSet Enum order Very fast and compact, for enum values 
Set<String> seen = new HashSet<>();
seen.add("a");      // true
seen.add("a");      // false: already there
seen.contains("a"); // true
seen.remove("a");

Also: iterator(), size(), isEmpty(), clear(). Two sets are equals() when they hold the same elements, in any order.

The classic use: removing duplicates, new HashSet<>(list), or answering "have I seen this before?" in O(1).

Trees

A tree is a hierarchy of nodes: one root, and each node has children. Unlike arrays and linked lists, it isn't linear.

Binary trees

Each node has at most two children.

  • Leaf: a node with no children.
  • Height: the number of edges on the longest path from the root to a leaf. An empty tree has height −1; a single node has height 0.
  • A tree of height h has at most 2^(h+1) − 1 nodes.
Type Rule
Full (strict) Every node has 0 or 2 children
Complete Every level full except maybe the last, which fills from the left
Perfect Every level completely full
Balanced At every node, the left and right heights differ by at most 1

A complete or balanced tree has height about log₂ n, so operations are O(log n). In the worst case (every node has one child) the tree is a line: height n − 1, operations O(n).

Traversal

Order Visit Use
Pre-order node, left, right Copy a tree
In-order left, node, right A BST in sorted order
Post-order left, right, node Delete a tree, evaluate expressions
Level-order level by level (BFS, a queue) Shortest path, levels

Trick: trace a path around the tree, keeping it on your left. Write a node down the 1st time you pass it for pre-order, the 2nd for in-order, the 3rd for post-order.

class Node {
    int data;
    Node left, right;
    Node(int data) { this.data = data; }
}

void inOrder(Node n) {
    if (n == null) return;
    inOrder(n.left);
    System.out.print(n.data + " ");
    inOrder(n.right);
}

My traversal code

As an array: a complete tree fits in an array with no pointers. For index i: left child 2i + 1, right child 2i + 2, parent (i − 1) / 2.

Height, recursively

int height(Node n) {
    if (n == null) return -1;                         // an empty tree
    return 1 + Math.max(height(n.left), height(n.right));
}

The + 1 counts the edge from this node down to its taller subtree.

Path from the root to a node

Do a BFS and remember each node's parent in a HashMap. When you reach the target, follow the parents back to the root.

if (current == target) {
    LinkedList<Node> path = new LinkedList<>();
    for (Node n = current; n != null; n = parent.get(n)) path.addFirst(n);
    return path;
}
// when adding children to the queue:
parent.put(current.left, current);

Counting levels with BFS

Process the queue one level at a time: at the start of each level, the queue holds exactly that level's nodes.

Queue<Node> q = new ArrayDeque<>(List.of(root));
int levels = 0;
while (!q.isEmpty()) {
    int size = q.size();                 // nodes on this level
    for (int i = 0; i < size; i++) {
        Node n = q.poll();
        if (n.left != null) q.offer(n.left);
        if (n.right != null) q.offer(n.right);
    }
    levels++;
}

Binary search trees (BST)

For every node: left subtree < node < right subtree. Search, insert and delete are O(log n) when the tree is balanced.

Insert 12 into the tree above: 12 < 15 → go left; 12 > 8 → go right; 12 > 11 → go right; 12 < 13 and 13 is a leaf → 12 becomes 13's left child. New values are always added as leaves.

Delete:

  • A leaf: just remove it.
  • One child: replace the node with its child.
  • Two children: replace its value with the smallest value in its right subtree, then delete that node.

Is it a valid BST? Pass down the allowed range:

boolean isValid(Node n, Integer min, Integer max) {
    if (n == null) return true;
    if ((min != null && n.data <= min) || (max != null && n.data >= max)) return false;
    return isValid(n.left, min, n.data) && isValid(n.right, n.data, max);
}

Or check that an in-order traversal comes out sorted.

A BST of minimal height from a sorted array

Take the middle element as the root, then build the left half and the right half the same way. [1, 2, 3, 4, 5] gives root 3, left subtree from [1, 2], right from [4, 5].

Node build(int[] arr, int start, int end) {
    if (start > end) return null;
    int mid = (start + end) / 2;
    Node node = new Node(arr[mid]);
    node.left = build(arr, start, mid - 1);
    node.right = build(arr, mid + 1, end);
    return node;
}

Height: best ≈ log₂(n + 1) − 1, worst n − 1. Self-balancing trees (AVL, red–black, used by TreeMap) keep it near log n automatically. B-trees have many children per node and are what databases use for indexes.

Heaps

A heap is a complete binary tree where every parent is smaller than its children (min-heap) or larger (max-heap). The children aren't ordered among themselves.

Insert: put the new value at the end of the array, then swap it with its parent while it's smaller (sift up). O(log n).

Remove the top: move the last element to the root, then swap it with its smaller child while it's bigger (sift down). O(log n).

Graphs

A graph is a set of vertices (nodes) joined by edges. Edges can be directed (one way) or undirected, and weighted (a cost) or not. Unlike trees, graphs can have cycles and separate parts.

BFS and DFS

Breadth-first search uses a queue: it explores all neighbours, then their neighbours, so it finds the shortest path in an unweighted graph.

void bfs(int start) {
    Queue<Integer> q = new ArrayDeque<>();
    Set<Integer> visited = new HashSet<>();
    q.offer(start);
    visited.add(start);
    while (!q.isEmpty()) {
        int v = q.poll();
        System.out.print(v + " ");
        for (int next : graph.getOrDefault(v, List.of())) {
            if (visited.add(next)) q.offer(next);   // add returns false if already seen
        }
    }
}

Depth-first search uses a stack (or recursion, which uses the call stack): it goes as deep as it can, then backtracks.

void dfs(int v, Set<Integer> visited) {
    if (!visited.add(v)) return;
    System.out.print(v + " ");
    for (int next : graph.getOrDefault(v, List.of())) dfs(next, visited);
}

Always mark nodes as visited, or a cycle makes the search loop forever.

Bidirectional search: run a BFS from both ends at once and stop where they meet. With k neighbours per node and distance d, that's about O(k^(d/2)) instead of O(k^d).

Topological sort

Orders the vertices of a directed acyclic graph (DAG) so every edge points forward: dependencies first. If package 1 needs 2, 2 needs 3, and 3 needs 4, build in the order 4, 3, 2, 1.

  • DFS-based: run DFS; add each node to a list after all its children are done (post-order). The list then puts dependencies first. O(V + E).
  • Kahn's algorithm: repeatedly take a node with no incoming edges, output it, and remove its edges. If nodes are left over, there's a cycle. O(V + E).

Minimum spanning tree

A spanning tree connects every vertex with no cycles. The minimum one has the smallest total edge weight (cheapest network of cables).

Algorithm Idea Time
Kruskal Sort the edges by weight; add each one unless it makes a cycle (checked with union–find) O(E log E)
Prim Grow one tree: always add the cheapest edge leaving it (with a min-heap) O(E log V)

Shortest paths: Dijkstra

For weighted graphs with no negative edges:

  1. Set every distance to ∞, except the start (0).
  2. Take the unvisited vertex with the smallest distance (use a min-heap).
  3. For each neighbour v of u: if dist[u] + weight(u, v) < dist[v], update dist[v].
  4. Repeat until every vertex is visited.

O((V + E) log V) with a heap (O(V²) with a simple array).

Algorithm strategies

Most problems are solved with one of a few strategies:

Strategy Idea Examples
Brute force Try everything Checking every pair
Greedy Take the best-looking choice at each step, never go back Kruskal, Prim, Dijkstra, making change with coins
Divide and conquer Split the problem, solve the parts, combine Merge sort, quick sort, binary search
Dynamic programming Solve each overlapping subproblem once and reuse the answer Fibonacci, knapsack, shortest paths
Backtracking Build a solution step by step; undo when stuck Sudoku, N-queens, permutations

Greedy is fast but only correct when local best choices add up to the global best. When they don't, use dynamic programming.

Merge sort

Divide and conquer:

  1. Split the array into two halves, and keep splitting until each piece has one element.
  2. Merge pairs of sorted pieces: compare their first elements, take the smaller, and repeat; when one runs out, copy the rest of the other.
void mergeSort(int[] a, int lo, int hi) {
    if (lo >= hi) return;
    int mid = (lo + hi) / 2;
    mergeSort(a, lo, mid);
    mergeSort(a, mid + 1, hi);
    merge(a, lo, mid, hi);
}

void merge(int[] a, int lo, int mid, int hi) {
    int[] tmp = new int[hi - lo + 1];
    int i = lo, j = mid + 1, k = 0;
    while (i <= mid && j <= hi) tmp[k++] = a[i] <= a[j] ? a[i++] : a[j++];
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= hi)  tmp[k++] = a[j++];
    System.arraycopy(tmp, 0, a, lo, tmp.length);
}

Good: always O(n log n), stable, and works on linked lists (it only reads in sequence). Costs: O(n) extra memory, and no shortcut for already-sorted input.

Quick sort

Pick a pivot; move smaller elements to its left and bigger ones to its right. The pivot is now in its final place. Sort the two sides the same way.

void quickSort(int[] a, int lo, int hi) {
    if (lo >= hi) return;
    int p = partition(a, lo, hi);
    quickSort(a, lo, p - 1);
    quickSort(a, p + 1, hi);
}

int partition(int[] a, int lo, int hi) {   // Lomuto: the last element is the pivot
    int pivot = a[hi], i = lo;
    for (int j = lo; j < hi; j++) {
        if (a[j] < pivot) swap(a, i++, j);
    }
    swap(a, i, hi);
    return i;
}

Sorts in place, so it suits arrays. The worst case, O(n²), happens when the pivot is always the smallest or largest (e.g. already-sorted input with a fixed pivot). A random pivot avoids it.

Heap sort

Turn the array into a max-heap, then repeatedly swap the top (the largest) to the end and restore the heap on the rest.

void heapSort(int[] a) {
    int n = a.length;
    for (int i = n / 2 - 1; i >= 0; i--) heapify(a, n, i);   // build the heap
    for (int end = n - 1; end > 0; end--) {
        swap(a, 0, end);          // the largest goes to the end
        heapify(a, end, 0);       // fix the heap on what's left
    }
}

void heapify(int[] a, int n, int i) {
    int largest = i, l = 2 * i + 1, r = 2 * i + 2;
    if (l < n && a[l] > a[largest]) largest = l;
    if (r < n && a[r] > a[largest]) largest = r;
    if (largest != i) {
        swap(a, i, largest);
        heapify(a, n, largest);
    }
}

The simple O(n²) sorts

Good for tiny or nearly sorted inputs, and for learning. Example input: 3 4 1 5 2.

Bubble sort: compare neighbours and swap them if they're in the wrong order. Each pass moves the largest remaining item to the end. Stop early if a pass makes no swaps.

for (int i = 0; i < n - 1; i++)
    for (int j = 0; j < n - 1 - i; j++)
        if (a[j] > a[j + 1]) swap(a, j, j + 1);

Selection sort: find the smallest remaining item and swap it into the next position.

for (int i = 0; i < n - 1; i++) {
    int min = i;
    for (int j = i + 1; j < n; j++) if (a[j] < a[min]) min = j;
    swap(a, i, min);
}

Insertion sort: take each item and slide it left into its place among the sorted ones, like sorting cards in your hand.

for (int i = 1; i < n; i++)
    for (int j = i; j > 0 && a[j] < a[j - 1]; j--)
        swap(a, j, j - 1);

Binary search

Look at the middle: if the target is smaller, search the left half; if bigger, the right half. Each step halves the range.

int binarySearch(int[] a, int target) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;     // avoids int overflow of (lo + hi)
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}

Interpolation search

Like binary search, but instead of the middle it guesses where the target should be, the way you open a phone book near "S" for "Smith":

int pos = lo + (int) ((long) (target - a[lo]) * (hi - lo) / (a[hi] - a[lo]));

Very fast on evenly spread data; slow when values are bunched up.

Dynamic programming

Dynamic programming (DP) speeds up recursion that solves the same subproblems again and again: solve each one once, store the answer, and reuse it. An exponential algorithm often becomes linear.

A problem suits DP when it has:

  • Overlapping subproblems: the same smaller problems keep coming back.
  • Optimal substructure: the best answer is built from best answers to the smaller problems.

Memoization (top-down)

Keep the recursion; cache each result the first time it's computed.

long fib(int n, long[] memo) {
    if (n <= 2) return 1;
    if (memo[n] != 0) return memo[n];        // already solved
    return memo[n] = fib(n - 1, memo) + fib(n - 2, memo);
}
// fib(50, new long[51])

Tabulation (bottom-up)

Drop the recursion; fill a table from the smallest case upwards.

long fib(int n) {
    long[] dp = new long[n + 1];
    dp[1] = 1;
    if (n > 1) dp[2] = 1;
    for (int i = 3; i <= n; i++) dp[i] = dp[i - 1] + dp[i - 2];
    return dp[n];
}

Here only the last two values are needed, so two variables would do: O(1) space.
