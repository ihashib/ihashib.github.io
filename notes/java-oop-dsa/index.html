Memory management

Stack memory

  • Stack memory is the portion of memory that the local variables like variables, methods etc are stored in.
  • Java uses Stack data structure which is LIFO.
  • This works well with the local variables as they are being executed line by line.

Heap memory

  • Heap memory is the portion of memory that is available to the program in runtime. This is where arrays are stored.
  • Heap memory has 2 parts
  • Young space
  • This is the new data
  • Old space
  • This is the old or unreferenced data
  • Example
  • Here main and print array methods and all the declared variables will be stored in the stack memory.
  • The array or objects are stored in heap memory during runtime.

Garbage collection

  • In Java, garbage collection is done automatically.
  • All the unreferenced objects are automatically cleaned and clearing heap memory space.
  • When the heap memory needs cleaning, the garbage collector clears the old space of the heap memory in order of FIFO.
  • Garbage collection can also be done in programs.

Annotations

Nullable

  • In Java, the @Nullable annotation is used to indicate that a variable, parameter, or method return value can be assigned a null value. This annotation is used in code that leverages null checks to improve the robustness of applications and reduce the likelihood of NullPointerExceptions.
  • The @Nullable annotation is typically used in the following situations:
  • Method parameters - When a method parameter can be assigned a null value, annotate it with @Nullable to indicate this fact.
  • Method return values - When a method can return a null value, annotate the return value with @Nullable to indicate this fact.
  • Fields and local variables - When a field or local variable can be assigned a null value, annotate it with @Nullable to indicate this fact.
  • By using @Nullable annotations in your code, you can help ensure that null values are handled appropriately and prevent NullPointerExceptions from occurring. Additionally, some code analysis tools can use these annotations to check for potential null pointer issues, helping you identify and fix bugs before they occur.

CompletableFutures

What

  • CompletableFuture is a class that promises to return a value in the future.
  • Doesn’t block main thread
  • Manages own threadpool
  • Compose by chaining multiple async operations.
  • Combine multiple completable futures.

When to use

  • Quick decision
  • Is the operation I/O bound? (Network, Database, File)
  • └─ YES → ✅ Consider CompletableFuture
  • └─ NO → Are multiple independent operations running?
  • └─ YES → ✅ Consider CompletableFuture
  • └─ NO → ❌ Use synchronous code
  • I/O bound operations (not sequentially dependent)
  • Independent operations
  • Background tasks
  • Timeout scenarios (when i want to timeout a call)
  • future.get(second, TimeUnit.SECONDS);

Create

completedFuture()
  • CompletableFuture<String> future = CompletableFuture.completedFuture(“Hello”);
  • System.out.println(future.join()) // immediately available
supplyAsync()
  • Returns a value
  • CompletableFuture<String> future = CompletableFuture.applyAsync(()-> { return “done”});
  • String result = future.join();
  • System.out.println(result);
runAsync()
  • Does not return value
  • CompletableFuture<void> future = CompletableFuture.runAsync(()-> sout(“Done”););
  • future.join();

Composition

thenApply()
  • Transforms the result synchronously
  • Use thenApply() for functions that return plain value
thenCompose()
  • Transforms the result asynchronously, returns another CompletableFuture.

Combination

thenCombine()
  • Combines 2 futures
  • CompletableFuture<String> userFuture = CompletableFuture.supplyAsync(()-> return “user”;);
  • CompleteableFuture<Integer> ageFuture = CompletableFuture.supplyAsuc(()-> return 20;);
  • CompletableFuture<String> combined = userFuture.thenCombine(ageFuture, (name, age> -> return name + age;)); // here ageFuture is the 2nd future to combine with
  • System.out.println(combined.join());
allOf()
  • Waits for all futures to complete
  • CompletableFuture<Void> all = CompletableFuture.allOf(f1, f2, f3);
anyof()
  • Waits for the first future to complete
  • CompletableFuture<Void> all = CompletableFuture.anyOf(f1, f2, f3);

Error handling

exceptionally()
  • CompletableFuture<String> userFuture = CompletableFuture.supplyAsync(()-> return “user”;)
.exceptionally(ex -> return ex;);

  • Can handle both result and exception

Functional Interface

What is it?

  • An interface that has exactly one abstract method. They are the basis for Lambda expressions and Method References.
  • They allow us to treat code (behavior) as data. We can pass a "function" as an argument to a method.

Common Types

  • Function<T, R>
  • Input: T
  • Output: R
  • Use: Transformation or Extraction. "Take this object and give me its ID."
  • Function<User, String> getEmail = user -> user.getEmail();
  • Predicate
  • Input: T
  • Output: boolean
  • Use: Filtering or Validation. "Test if this object meets a condition."
  • Predicate<User> isActive = user -> user.getStatus() == ACTIVE;
  • Consumer
  • Input: T
  • Output: void
  • Use: Side effects. "Take this object and print it / save to DB."
  • Consumer<String> printer = msg -> System.out.println(msg);
  • Supplier
  • Input: None
  • Output: T
  • Use: Factories / Lazy generation. "Give me a new object."
  • Supplier<Double> random = () -> Math.random();

Threading

Process

  • An instance of a computer program with one or many threads.
  • Processes have their own address space in memory.

Thread

  • A single sequence of execution within a process.
  • Threads share memory of processes.

Multitasking

  • A computer’s ability to perform multiple jobs concurrently.

MultiThreading

  • Multiple threads within a single program.

Application Thread

  • When we execute a Java program
  • The JVM creates a thread object that is defined by main()
  • When main returns, the thread dies.

Multiple Threads in an application

  • Each thread has its private run time heap memory.
  • When two threads execute the same method, they will have different copies of the method, including local variables.
  • All threads see the same dynamic memory of the process.
  • Two different threads can act on the same objects and same static fields concurrently.

  • The program executes t1.start() then goes on to the next line.
  • So this may cause program flow issues.

Hash tables
  • Hash Function
  • A hash function is like a magical mathematical recipe. It takes in data of any size (a word, a sentence, a whole file) and churns out a unique, fixed-size output called a "hash value" or "hash".
  • Think of it like a digital fingerprint for your data.
  • The data is stored in an array, where each element has an unique index. The index comes from the mod of the hash function of the key and array size. Thus search and insertion of data is very fast.
  • index = getHashCode(key)%arr.length
  • Data is stored in key value pairs using a hashing function.
  • Let a hash function H(x). H(x) maps x value at x%10 index. Here 10 is the array size.
  • Example
  • 11, 12, 13, 14, 15 is mapped at the 1,2,3,4,5 index of an array.
  • Implementation
    • The hash function always gives the index on the array from the key.
    • Use a manual linkedlist for storing key value pairs
    • Linkedlist because Hash function can cause the same index for different values.
    • When the hashed index of the array is found, we need to store and retrieve key and values considering that different keys can have same array index (because of the hash)
    • So when inserting or retrieving, go to the index then search the linkedlist for the key

Minimal height
  • In a binary search tree, the height (the number of edges in the longest path from the root to a leaf node) plays a critical role in the speed of operations like searching, insertion, and deletion. The shorter the tree, the fewer comparisons you need to make to find an element.
  • Minimal Height: What It Means
  • A binary search tree with "minimal height" is the most balanced tree you can construct from a given set of sorted data. Here's why this is important:
  • Optimal Search Efficiency: A balanced BST ensures that the search time complexity remains at O(log n), where n is the number of nodes. This means that as the tree grows, the number of comparisons needed to find an element increases relatively slowly.
  • Minimal Height Algo
  • Given a sorted array, minimizing the BST's height involves these key steps:
  • Find the Middle Element: The middle element of the array becomes the root of the tree. This choice is strategic.
  • Recurse Leftovers: The portion of the array to the left of the middle element becomes the left subtree, and the portion to the right becomes the right subtree.
  • Repeat on Subarrays: Recursively apply steps 1 and 2 to the subarrays until there are no more elements.
  • Illustrative Example
  • Let's say you have the sorted array [1, 2, 3, 4, 5]. Here's how a minimal height BST would be created:
  • The middle element, 3, becomes the root.
  • The left subarray [1, 2] and right subarray [4, 5] are formed.
  • Recursively, 2 becomes the root of the left subtree, and 4 becomes the root of the right subtree.
  • Finally, 1 becomes the left child of 2, and 5 becomes the right child of 4.
  • Code
Node minimalBst(Int[] arr, int start, int end){
   if(node == null) return;
   int mid = (start + end)/2;
   Node node = new Node(arr[mid]);
   node.left = minimalBst(arr, start, mid-1);
   node.right = minimalBst(arr, mid+1, end);
   return node;
}

private boolean isValidBSTHelper(Node node, Integer min, Integer max) {
   if (node == null) return true; // Empty subtree is valid
   if (min != null && node.data <= min) return false;
   if (max != null && node.data >= max) return false;
   return isValidBSTHelper(node.left, min, node.data) &&

}

Merge sort n logn

  • A divide and conquer algorithm and done in a recursive way.
  • Time complexity: O(n logn)

Algorithm

  • Take the initial array and divide equally into 2 sub arrays.
  • Recursively divide those 2 sub arrays into their own sub arrays, usually done one subarray first, then the next.
  • When only one element is present in an array, return. This is the recursion breaking condition.
  • When all the arrays have one element, merge them one by one.
  • The merge function algo works in a recursive way.
  • Take the 2 sub arrays into the merge function and see which one is bigger, put the bigger one into the sorted array. Since we don’t know which sub array is bigger, we use a while loop and run it until one or both sub arrays run out of elements.
  • If there are still elements remaining in one or both arrays, we put them at the back of the sorted array and return.

Applications

  • Merge sort does not need random access, it uses sequential access. This using a linked list is best with merge sort as arrays take more space and with array implementation we need a temporary array.

Drawbacks

  • Takes extra space.
  • Slower than other sorting algorithms.
  • Doesn’t have an array sorted check.

Quick sort n logn

  • When you think about Quick sort, think of a pivot.
  • Also a divide and conquer algorithm that uses recursion.
  • Time complexity: O(n logn), /Theta(n^2)

Algorithm

  • Sorts the array by picking a pivot element. Then sorts the other elements of the array by following
  • Elements bigger than the pivot have to be on the right.
  • Elements smaller than the pivot have to be on the left.
  • After swapping the big and small elements, we place the pivot at the convergence point of the iterators. So the pivot element is placed at the final sorted position.
  • Then we sort the right and left remaining array elements in this fashion until the whole array is sorted.
  • Partition
  • Select the first element of the array as pivot.
  • 2 variables, high and low are pointing to the first and last element.
  • We compare the low elements with pivot, if the element is bigger than the pivot, we keep the low index.
  • Then we compare the high elements with pivot, if the element is lower than the pivot, we keep the high index.
  • Then if low is less than high index, then we swap the elements.
  • When low and high converge, we stop swapping and swap the pivot with the high index. Now the pivot is sorted.
  • Now the left of the pivot is smaller and the right is bigger.
  • So we need to sort those elements in a similar way, so we return the pivot position, which is the high index.
  • Recursion
  • This method checks if low is less than high, this is the breaking condition.
  • We pass the array, low and high values to the partition method for the first time and we get the first pivot point.
  • Now we pass the left of the pivot to the recursion.
  • Then pass the right of the pivot to the recursion.
  • Low will be bigger than high at a point and the recursion will break.
  • PENDING: illustrations
  • Quick sort is best for arrays as this does not require an additional array which takes more space.

  • // Recursively heapify the affected sub-tree

Dynamic Programming

What is it?

  • Unlike greedy methods where a set algorithm is used to solve a problem, in dynamic programming we explore all possible solutions and pick the best one. It’s an optimization over recursion, where a recursive algorithm can take exponential time, optimization can lead to a linear time.

Types of DP

Memoization (Top down)

  • Recursion problems that have to calculate the same subproblem multiple times, we use an array to save the already calculated solutions. Then, when an already calculated subproblem comes again, we use the saved data.
  • Starts from the top or destination state and calculates itself to the base case recursively.
  • Example:
  • fibo(n, memo[])
  • if(n == 1 || n ==2)
  • return 1
  • if(memo[n] != -1){
  • return memo[n]
  • return fibo(n-1, memo)+fibo(n-2, memo)
  • Here, memo is used to save the already calculated subproblems and used when the same subproblem occurs again.

Tabulation (Bottom up)

  • Like memoization, tabulation uses an array to build from the base case to the destination state. As a result it’s a bottom up approach that uses iterations to solve the problem.
  • Example:
  • fibo(n)
  • memo[]
  • mem[0] = 1, memo[1] = 1;
  • for(i = 2, till n)
  • memo[i] = memo[i-1]+memo[i-2];
  • return memo;
  • As we can see, the tabulation method uses the array to build the solution from the bottom.

Memoization vs Tabulation

  • Memoization uses recursion
  • tabulation uses iteration.
  • Memoization uses the array as a cache that may or may not be filled
  • tabulation uses the array to build its solution so it will be filled.
  • Memoization is best when all subproblems are not required to be solved
  • tabulation is best when all subproblems need to be solved.
