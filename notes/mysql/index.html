SQL Manual Trace
  • Table Understanding
  • Columns & Data Types: Be aware of the names, data types (text, number, date, etc.) of columns in all involved tables.
  • Sample Data: Visualize a small subset of data in your head, or sketch it out.
  • Break Down the Query (Order Matters!)
  • SELECT:
    • Identify columns for the final output.
    • Note aggregate functions (SUM, COUNT, AVG, etc.), if any.
  • FROM: Your base table(s).
  • JOIN:
    • Type of join (INNER, LEFT, RIGHT, FULL)
    • Join condition (ON ...) – the key to linking tables
  • WHERE: Pre-filtering of rows.
  • GROUP BY: Columns used for grouping.
  • HAVING: Filters on groups formed by GROUP BY.
  • ORDER BY: Sorting of final results (not relevant to intermediate steps).
  • Step-by-Step "Simulation"
  • Start with your 'Sample Data': Imagine your mini version of the table(s).
  • WHERE Filter: Eliminate rows not meeting the WHERE criteria.
  • JOIN Action:
    • INNER JOIN: Only keep rows having matches in BOTH tables as per the ON condition.
    • LEFT/RIGHT JOIN: Keep ALL rows from the specified table, fill missing matches with NULL.
    • FULL JOIN: Keep ALL rows from both, fill gaps with NULL.
  • GROUP BY Form Groups: Mentally create sub-groups for each unique value in the GROUP BY columns.
  • Aggregates in SELECT:
    • AVG: Imagine calculating the average within each group.
    • SUM: Picture summing up values within each group.
    • COUNT: Visualize counting rows within each group.
  • HAVING Eliminate Groups: Remove whole groups that don't fulfill the HAVING condition.
  • SELECT Finalize: Pick out only the columns needed from the remaining data.
  • Visual Representation: Simple 'Order' Example
    • SELECT department, COUNT(employee_id) as employee_count
FROM employees
GROUP BY department
ORDER BY employee_count DESC;
  • Visualization:
    • Table ('employees')
    • Imagine a miniature version

  • Create mental groups for 'Sales', 'Marketing', etc.
  • SELECT & COUNT
    • Calculate employee count within each group

Data Definition Language (DDL)

CREATE

  • Database
    • CREATE DATABASE database_name
  • Table
    • CREATE TABLE table_name (column_name Data_type Constraint,.....)
    • Constraints
      • NOT NULL - Restricts NULL value from being inserted into a column.
      • CHECK - Verifies that all values in a field satisfy a condition.
      • DEFAULT - Automatically assigns a default value if no value has been specified for the field.
      • UNIQUE - Ensures unique values to be inserted into the field.
      • INDEX - Indexes a field providing faster retrieval of records.
      • Primary Key(column_name)
      • NULL, NOT NULL
      • AUTO INCREMENT
      • DEFAULT = “ ”
      • Foreign Key(column) REFERENCES foreign_table(foreign_pk)
    • Example:
      • CREATE TABLE employees(
        • id NOT NULL AUTO_INCREMENT,
        • Name NOT NULL,
        • Phone NOT NULL,
        • fId NOT NULL,
        • PRIMARY KEY(id)
        • FOREIGN KEY(fId) REFERENCES department(DEVOPS));

SQL Logical operators

ALL

  • “return TRUE if the comparison is TRUE for ALL of the values in the column that the subquery returns.”
  • For example: SELECT s1 FROM t1 WHERE s1 > ALL (SELECT s1 FROM t2);

AND

  • All conditions must be true
  • SELECT column_name FROM table_name WHERE condition1 AND condition2

ANY

  • Just like ALL but any of the subqueries can be TRUE;

BETWEEN

  • To select values between 2 values, like salary > 50 AND salary < 100, replace this with “salary BETWEEN 50 AND 100”.
  • SELECT column_name FROM tablename WHERE column_name BETWEEN value1 AND value2;

IN

  • Shorthand for multiple OR commands. NOT IN will cause the reverse.
  • SELECT column_names FROM table_name WHERE column_name IN (con1, con2);

NOT

  • Negative operator
  • SELECT column_name FROM table_name WHERE NOT(condition1);
    • This will print the opposite of condition 1, example NOT(department=’CSE’), this will print all data except CSE department data.

OR

  • At Least one condition has to be true
  • SELECT column_name FROM table_name WHERE condition1 OR condition2

LIKE

  • LIKE is used with WHERE to find a specific pattern in data.
  • SELECT column_name FROM table_name WHERE column_name LIKE condition
  • Example
    • All names that start with letter M.
    • SELECT * FROM employees WHERE First_name LIKE M%
  • % indicates one or many characters.
  • _ indicates only one character.
  • Note: LIKE and ILIKE do the same thing but LIKE is case sensitive.

EXIST

LIMIT

  • Limits the amount of data being shown.
  • SELECT column_name FROM table_name LIMIT value
    • NOTE: LIMIT skip_values, value. like: 5, 2. After 5 data, print 6 and 7.

Handling NULL

COALESCE

  • When there are null values and want to use a default value.
  • SELECT COALESCE(email, ‘email not found’) FROM user_data

Division by 0 with NULLIF

  • NULLIF(val1, val2) returns val1 if val1 and val2 are not equal and if they are equal it returns null.
  • Dividing anything with NULL will not give an error.
  • SELECT COALESCE(10 / NULLIF(0,0), 0)
  • This will return null and not an error.

SQL Causes

GROUP BY

  • The GROUP BY statement groups rows that have the same values into summary rows, like "find the number of customers in each country".
  • This is basically finding categories of each kind of row from the table.
  • The GROUP BY statement is often used with aggregate functions (COUNT(), MAX(), MIN(), SUM(), AVG()) to group the result-set by one or more columns.
  • SELECT column_name(s)
  • FROM table_name
  • WHERE condition
  • GROUP BY column_name(s)

HAVING

  • The HAVING clause was added to SQL because the WHERE keyword cannot be used with aggregate functions and after Group By.
  • SELECT column_name(s)
  • FROM table_name
  • WHERE condition
  • GROUP BY column_name(s)
  • HAVING condition
  • ORDER BY column_name(s);

ORDER BY

  • Used to sort the output of select.
  • ASC for ascending which is default and DESC for descending.
  • SELECT column_names FROM table_name ORDER BY column_name ASC;
    • NOTE: In MySQL the column name after ORDER BY can be any of the columns and not from the SELECT part. But in other DBMS, this is not allowed.
    • example: SELECT name, country FROM employees ORDER BY salary DESC

OVER( Window functions)

  • Used for Window Functions
    • Aggregate functions return a single row for the multirow data given but window functions return calculated results for each row in the given windows(Groups of data).
    • Can be applied on aggregate functions to return window functions.
    • The functions return table views with an added column and doesn’t modify any contents from the table.
  • Syntax
    • SELECT column_name,
      • <WINDOW_FUNCTION>
      • OVER(PARTITION BY column ORDER BY column ASC/DESC) as column
        • OVER() is the bread and butter to window function
        • PARTITION BY is like GROUP BY but the former returns multirow results and later returns a single row result.
        • ORDER BY can be used after PARTITION BY as it’s like GROUP BY.
  • Types of window functions
    • Aggregate functions
      • Same functionality as normal aggregate functions but returns all row result

SELECT

  • region,
  • sales_amount,
  • SUM(sales_amount) OVER (PARTITION BY region) AS regional_total
  • FROM sales;
  • Ranking functions
    • RANK()
      • Ranks the partitions/groups/categories with gaps in the ranking sequence.
      • If same ranked categories are found, then they are ranked the same but the next category will have skipped ranking. The skip is equal to the number of the same value category.
        • Example:
        • Table:
          • Name Value
          • east 100
          • west 100
          • north 101
          • south 102
        • SELECT Name, Value,
          • RANK() OVER (PARTITION BY Value ORDER BY Value ASC) as rank
        • FROM tableName;
          • Name Value rank
          • east 100 1
          • west 100 1
          • north 101 3
          • south 102 4
    • DENSE_RANK()
      • Ranks the partitions without gaps in the ranking sequence.
      • If same ranked partitions are found, then they are sequenced the same and the next partition is sequenced without any skips.
      • SELECT Name, Value,
        • RANK() OVER (PARTITION BY Value ORDER BY Value ASC) as rank
      • FROM tableName;
        • Name Value rank
        • east 100 1
        • west 100 1
        • north 101 2
        • south 102 3
    • ROW_NUMBER()
  • Analytic functions
    • LEAD(), LAG(), NTILE() (TBS)

Common Table Expressions (CTE)
  • CTE are named subqueries inside a SQL query.
  • A CTE is limited to on memory and the scope is inside the query it’s defined in.

Syntax structure

  • WITH cte_name (col1, col2…) AS (<your SQL queries>)
  • SELECT * FROM cte_name;
  • Note:
  • Here, WITH is the keyword for CTE.
  • (col1 DataType, col2 dataType…)
  • Explicit override, it’s good practice to name your columns
  • The explicit syntax is the same as the CREATE TABLE command.
  • If the data type does not match with original table, then it converts to String.
  • Implicit declaration of the cte_table will inherit all the columns and datatypes.
  • Example
  • Calculate the average sales per region, and then find regions with sales above that average:
WITH regional_averages AS (
   SELECT region, AVG(sales_amount) AS avg_sales
   FROM sales_data
   GROUP BY region
)
SELECT region, sales_amount
FROM sales_data
JOIN regional_averages ra ON sales_data.region = ra.region
WHERE sales_data.sales_amount > ra.avg_sales;

Temp Tables

  • Temp tables are regular tables that are stored in a temporary space within the database.
  • Types
  • Local temp tables
  • Syntax: #local_table
  • Exists in the current session, destroyed when ending the session.
  • Global temp tables
  • Syntex: ##global_table
  • Exists in all sessions until explicitly deleted.
  • Example: Sales Data Filtering
  • CREATE TABLE #high_value_orders (
  • order_id INT,
  • customer_id INT,
  • order_amount DECIMAL(10,2)
  • );
  • INSERT INTO #high_value_orders
  • SELECT order_id, customer_id, total_amount
  • FROM sales
  • WHERE total_amount > 1000;
