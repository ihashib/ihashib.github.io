Getting started3 topics

Installing ESP-IDF and a first project

ESP-IDF is Espressif's official framework for programming the ESP32 in C. The easiest way in is the Espressif IDF extension for VS Code. There's a video walkthrough too.

Ubuntu

  1. In VS Code, open Extensions, search Espressif IDF and install it.
  2. Open the extension, choose Express and follow the steps.

Windows

  1. Open the ESP-IDF get-started page, find Manual Installation and pick Windows Installer.
  2. Download the Universal Online Installer and run it.
  3. If the system scan offers Apply Fixes, press it. Then choose Download ESP-IDF and a release version (for example v4.4).
  4. Make a folder C:\esp with two folders inside: idf and tools. Point the installer at them.
  5. Choose Full installation and install.
  6. In VS Code, install the ESP-IDF extension, press F1 and pick Use Existing Setup (or Express if it isn't offered).

No spaces in any folder or project name. ESP-IDF fails on them.

A first project

  1. F1 → ESP-IDF: New Project, and give it a name (no spaces).
  2. Board: Custom board → ESP32 module.
  3. Template: ESP-IDF → sample_project, then Create project using template.
  4. If asked for a kit, pick Scan for kits. Your code goes in main/main.c.

For better code completion, add this to .vscode/settings.json:

"C_Cpp.intelliSenseEngine": "Default"

Build, flash and monitor

Use the buttons in the VS Code status bar, or the terminal:

idf.py build                       # compile
idf.py -p COM3 flash monitor       # build if needed, flash, then show the serial output

Replace COM3 with your board's port (/dev/ttyUSB0 on Linux). Press Ctrl+] to leave the monitor.

Don't keep the project in a Google Drive folder: the build fails there.

Logging

esp_log.h prints messages with a tag and a level, in colour, in the monitor.

#include "esp_log.h"

static const char *TAG = "app";

ESP_LOGE(TAG, "Error");     // red
ESP_LOGW(TAG, "Warning");   // yellow
ESP_LOGI(TAG, "Info");      // green
ESP_LOGD(TAG, "Debug");
ESP_LOGV(TAG, "Verbose");

Debug and Verbose are hidden by default. Turn them on in idf.py menuconfig → Component config → Log output.

Programming basics5 topics

Delay

ESP-IDF runs on FreeRTOS, so you wait with vTaskDelay. It counts in ticks, not milliseconds; divide by portTICK_PERIOD_MS to convert.

#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

vTaskDelay(1000 / portTICK_PERIOD_MS);   // wait 1000 ms

While a task waits, the chip is free to run other tasks.

Blink

The "hello world" of microcontrollers: the built-in LED on pin 2 (ESP32-WROOM-32 boards) on and off every second.

#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "driver/gpio.h"

#define LED_PIN      2
#define BLINK_PERIOD 1000

void app_main(void)
{
    gpio_reset_pin(LED_PIN);
    gpio_set_direction(LED_PIN, GPIO_MODE_OUTPUT);

    while (1) {
        gpio_set_level(LED_PIN, 1);
        vTaskDelay(BLINK_PERIOD / portTICK_PERIOD_MS);
        gpio_set_level(LED_PIN, 0);
        vTaskDelay(BLINK_PERIOD / portTICK_PERIOD_MS);
    }
}

Nothing to change in menuconfig: build and flash.

GPIO

General-purpose pins, read or written as 1 or 0. Full reference: ESP-IDF GPIO docs.

#include "driver/gpio.h"

gpio_reset_pin(PIN);
gpio_set_direction(PIN, GPIO_MODE_OUTPUT);

gpio_set_level(PIN, 1);          // digital out: 1 or 0
int d_in = gpio_get_level(PIN);  // digital in
Mode Pin can
GPIO_MODE_DISABLE Do nothing (off)
GPIO_MODE_INPUT Read only
GPIO_MODE_OUTPUT Write only
GPIO_MODE_OUTPUT_OD Write, open-drain
GPIO_MODE_INPUT_OUTPUT Read and write
GPIO_MODE_INPUT_OUTPUT_OD Read and write, open-drain

Open-drain means the pin can only pull the line low; a resistor pulls it high. It's what shared lines such as I²C need.

Analog input (ADC)

The ADC turns a voltage on a pin into a number. The ESP32 has two ADCs:

ADC1 GPIO ADC2 GPIO
CHANNEL_0 36 CHANNEL_0 4
CHANNEL_1 37 CHANNEL_1 0
CHANNEL_2 38 CHANNEL_2 2
CHANNEL_3 39 CHANNEL_3 15
CHANNEL_4 32 CHANNEL_4 13
CHANNEL_5 33 CHANNEL_5 12
CHANNEL_6 34 CHANNEL_6 14
CHANNEL_7 35 CHANNEL_7 27
CHANNEL_8 25
CHANNEL_9 26

Use ADC1 when you can. ADC2 is shared with Wi-Fi and can't be read while Wi-Fi is on.

1. Set the attenuation

An ESP32 pin can only measure a limited voltage range. Attenuation widens it:

#include "driver/adc.h"
#include "esp_adc_cal.h"

adc1_config_channel_atten(ADC1_CHANNEL_6, ADC_ATTEN_DB_11);

2. Set the width (resolution)

ADC_WIDTH_BIT_9 to ADC_WIDTH_BIT_12. The default is 12 bits, a number from 0 to 4095.

adc1_config_width(ADC_WIDTH_BIT_DEFAULT);
int raw = adc1_get_raw(ADC1_CHANNEL_6);

3. Calibrate and convert to millivolts

Every chip's reference voltage is a little different, so calibrate before converting:

esp_adc_cal_characteristics_t adc1_chars;
esp_adc_cal_characterize(ADC_UNIT_1, ADC_ATTEN_DB_11, ADC_WIDTH_BIT_DEFAULT, 0, &adc1_chars);

uint32_t mV = esp_adc_cal_raw_to_voltage(adc1_get_raw(ADC1_CHANNEL_6), &adc1_chars);

These adc1_* calls are ESP-IDF 4.x. From version 5 they are replaced by the adc_oneshot_* API.

Keyboard input

Read a line typed into the serial monitor. getchar() doesn't wait: it returns 0xFF when nothing has been typed, so the loop checks for that and pauses between tries.

#include <stdio.h>
#include <string.h>

void app_main(void)
{
    char c = 0;
    char str[100];
    memset(str, 0, sizeof(str));

    while (c != '\n') {              // stop at Enter
        c = getchar();
        if (c != 0xff) {
            str[strlen(str)] = c;
            printf("%c", c);         // echo it back
        }
        vTaskDelay(100 / portTICK_PERIOD_MS);
    }
}
Wireless and serial1 topic

Bluetooth Low Energy (BLE)

Two parts of BLE matter most:

  • GAP (Generic Access Profile) handles advertising and connecting. It's what makes the device visible to phones, and decides who may connect.
  • GATT (Generic Attribute Profile) handles data once connected. It runs on the Attribute Protocol (ATT) and gives every device the same structure, so devices from different makers understand each other. A good intro: Getting Started with BLE, ch. 4.

The server (here, the ESP32) owns the data. Each attribute has a UUID, a value and permissions (read, write, notify). Make your own UUIDs with a UUID v4 generator.

The ESP-IDF examples

In ESP-IDF's examples/bluetooth folder:

Example Shows
gatt_server_service_table A service built from an attribute table (the recommended way)
gatt_server Adding attributes one by one
ble_spp_server Sending UART data to a phone, like a serial cable

Try it: create a project from the GATT server template and flash it. Then connect with a BLE terminal app on your phone, long-press the device, choose Edit → Custom, and enter the UUIDs.

How the service-table example works

Walkthrough: GATT server service table.

Then events arrive in the handlers:

  • GATT event handler: gives each app profile its GATT interface (gatts_if) and passes events on to that profile's handler.
  • ESP_GATTS_REG_EVT: sets the device name, the advertising and scan-response data, and creates the attribute table. Each entry is an esp_gatts_attr_db_t:
    esp_attr_control_t attr_control;   // who answers: the stack or your code
esp_attr_desc_t    att_desc;       // UUID, permissions, value
  • ESP_GATTS_WRITE_EVT: the phone wrote something. param->write.value is raw bytes: cast it to the type you expect.
  • ESP_GATTS_READ_EVT: the phone asked to read a value.
  • GAP event handler: advertising started, connection parameters updated, and so on. Set the MTU (the largest packet) here.
